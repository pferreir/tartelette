# `ssd1306`: monochrome OLED

The Solomon Systech SSD1306, the controller of the common 128×64 and 128×32
OLED modules, on I2C.

## Keys

| Key | Type | Default | |
|-----|------|---------|---|
| `bus` | I2C bus | required | the bus it sits on |
| `addr` | 0x3C..0x3D | `0x3C` | I2C address (0x3D with SA0 high) |
| `height` | `32` \| `64` | `64` | rows of the panel; it is 128 wide |
| `color` | `white` \| `blue` \| `yellow` \| `green` | `white` | the colour the pixels glow |

```toml
[buses]
i2c1 = { sda = 2, scl = 3 }

[parts.oled]
kind = "ssd1306"
bus = "i2c1"
height = "32"
```

## What's modelled

Each I2C write starts with a control byte that says whether commands or
display data follow (and, with Co set, that only one byte does). A command's
arguments may come in later writes, as drivers that send a byte a write do.
Data goes to the 128×64-bit display RAM, a byte a column of 8 rows, at the
address pointer, which moves on as the addressing mode says: horizontal,
vertical or page (with the column and page address windows, and the page
mode's start commands).

What the glass shows follows display on/off, contrast (as brightness),
normal or inverse display, entire display on, segment remap, COM scan
direction, display start line, display offset and the multiplex ratio. The
glass sits as on the common modules: upright with the segments remapped
(`A1`) and the COM scan reversed (`C8`), the settings drivers send.

## Panel

The screen, scaled to its item. `rotate` turns it, as for the
[`st7789`](st7789.md). Headless, `--dump-screen NAME=FILE` saves it.

## Events

`update`, with the bytes of display data a write carried, at its STOP.

## Not modelled

Scrolling (its commands are taken and ignored), the alternative COM pin
configuration, reads (they return 0), and SPI or parallel interfaces.
