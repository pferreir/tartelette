# `mcp23008`: I2C port expander

The Microchip MCP23008: eight GPIOs behind an I2C interface, with an
interrupt output. On the BTL-01 it carries four soft-key buttons (inputs with
pull-ups) and the four gate outputs.

## Keys

| Key | Type | Default | |
|-----|------|---------|---|
| `bus` | `i2c0` \| `i2c1` | | the bus it sits on, declared under `[buses]` |
| `addr` | `0x20`..`0x27` | `0x20` | I2C address, set by the A2..A0 pins |
| `int` | GPIO, shareable | | the GPIO its INT output drives |

```toml
[buses]
i2c1 = { sda = 2, scl = 3 }

[parts.expander]
kind = "mcp23008"
bus = "i2c1"
addr = 0x20
int = 16
```

`int` can be shared between several expanders when they are configured as
open drain, as on a real board.

## What's modelled

All eleven registers, with the address pointer auto-incrementing (and
wrapping) unless `IOCON.SEQOP` turns sequential mode off. Input polarity,
the internal pull-ups, interrupt-on-change against the previous value or
`DEFVAL`, `INTF` and `INTCAP` capture, and the INT pin's polarity and open-
drain setting.

A pin's level comes from whoever drives it: the expander itself (when it is
an output), the outside world (a button on the panel, an `--input`), or its
pull-up. Undriven, it floats low.

Interrupts are evaluated whenever a pin or a register changes.

## Panel

A cell per pin, lit while the pin is high. One expander can have several
panel items, so inputs and outputs can sit apart:

```toml
[panel]
expander = [
  { at = [0, 3], span = [2, 1], label = "Soft keys", pins = [4, 5, 6, 7], keys = ["1", "2", "3", "4"] },
  { at = [2, 3], span = [2, 1], label = "Gates", pins = [0, 1, 2, 3], mode = "view", labels = ["A", "B", "C", "D"] },
]
```

| Option | | Default |
|--------|---|---------|
| `pins` | which pins, in order | all eight |
| `mode` | `hold`: drive the pin while the cell is held; `toggle`: each click flips it; `view`: show only | `hold` |
| `active` | `low` or `high`: the level a cell drives its pin to | `low` |
| `keys` | a keyboard key per pin | |
| `labels` | text per cell instead of the pin number | |

## Events

`pins`, with the eight pin levels as a byte (bit 0 = GP0), whenever any of
them changes.

## Actions

`gp0` .. `gp7`, with `1` to drive the pin high, `0` to drive it low and `-1`
to let go:

```sh
--input expander:gp4=0@1000000 --input expander:gp4=-1@1100000   # tap soft key 1
```

## Not modelled

The I2C timing (transfers are instantaneous, see
[rp2040.md](../rp2040.md#i2c)) and `IOCON.DISSLW`.
